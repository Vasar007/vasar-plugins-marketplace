# Task comments

The master agent reads this file before it writes Task Comment #1 or Task Comment #2 of `SKILL.md`. A run on a plain request posts no task comment. The time of each post is in `SKILL.md`.

## Rules for both comments

Write the comment in English, and keep it short. Post it to the task through the MCP server of the task provider. If the provider supports Markdown comments, use short headings and flat bullets. Else post the same content as plain text. If the post fails, stop at once. After a successful post, record the time and the comment ID of the provider (if one exists) in `taskComments` of `pipeline-state.json`.

## Task Comment #1

The comment summarizes:

- The task objective in plain English
- The approved implementation approach from `spec.md`
- The planned test strategy from `test-plan.md`
- The key constraints, risks, or migrations that the analysis names
- That the implementation starts now
- A footer line: "This comment was generated by Claude Code"

## Task Comment #2

The comment summarizes:

- What the run implemented
- The added or updated tests, and the latest test status
- Any documentation updates
- The results of the code review and the security review, or a note that the run skipped one of them
- That the task moves into finalization next
- A footer line: "This comment was generated by Claude Code"
