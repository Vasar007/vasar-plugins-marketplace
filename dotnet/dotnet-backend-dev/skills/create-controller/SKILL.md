# Create Controller Implementation

Create WebAPI controller implementations in your Web API project following a spec-first approach with generated interfaces.

## Spec-First Approach

**CRITICAL**: Controllers are NOT created manually. Instead:

1. **Define OpenAPI spec** in `swagger.json` (with `[TBD]` prefixes for user-facing content)
2. **NSwag generates** interface and base controller in `AutoGenerated/ControllersAndModels.Generated.cs`
3. **You implement** the interface in `I{Feature}ControllerImpl` class

## Architecture

```text
swagger.json (OpenAPI spec)
    ↓ NSwag generates
AutoGenerated/ControllersAndModels.Generated.cs
    ↓ contains
Rest.I{Feature}Controller (interface)
    ↓ implemented by
{Feature}ControllerImpl : {ServiceName}ControllerBase
    ↓ delegates to
Application Services (business logic)
```

## File Location

Controller implementations mirror swagger.json structure:

- `/api/v1/retail-stores` → `Controllers/Retail/Stores/StoresControllerImpl.cs`
- `/api/v1/partner-organizations` → `Controllers/Partner/Organizations/OrganizationsControllerImpl.cs`
- `/api/v1/logistics/warehouses` → `Controllers/Logistics/Warehouses/WarehousesControllerImpl.cs`

```csharp
/// <summary>

/// </summary>
internal sealed class {Feature}ControllerImpl : {ServiceName}ControllerBase, Rest.I{Feature}Controller
{
    private readonly I{Service} _service;

    /// <summary>
    /// Initializes a new instance of the <see cref="{Feature}ControllerImpl"/> class.

        IErrorFactory errorFactory,
        I{Service} service,
        IIdentifierValidator identifierValidator)
        : base(errorFactory)
    {
        _service = service.ThrowIfNull();
        _identifierValidator = identifierValidator.ThrowIfNull();
    }

    // Method implementations here
}
```

## Async Operation Pattern (Long-Running)

For operations that take time (onboarding, closing, editing), use session-based async:

```csharp
public async Task<ActionResult<Rest.SessionLink>> OnboardStoreAsync(
    Rest.StoreOnboardingRequest request,
    CancellationToken cancellationToken = default)
{
    try
    {
        request.ThrowIfNull();
        cancellationToken.ThrowIfCancellationRequested();

        // Convert REST → Domain
        var onboardingRequest = request.ToDomainStoreOnboardingRequest();
        
        // Delegate to service (returns session)
        var sessionResponse = await _service.StartOnboardingAsync(onboardingRequest, cancellationToken);
        
        // Return 202 Accepted with session link
        return Accepted(sessionResponse.ToRestSessionLink());
    }
    catch (Exception ex)
    {
        return ServerException(ex);
    }
}
```

## Sync Operation Pattern (Fast Operations)

For quick operations (get by ID, list), return directly:

```csharp
public async Task<ActionResult<Rest.Store>> GetStoreAsync(
    Guid storeId,
    CancellationToken cancellationToken = default)
{
    try
    {
        cancellationToken.ThrowIfCancellationRequested();

        // Validate identifier
        if (_identifierValidator.IsInvalidIdentifier(storeId))
            return BadRequest(StringResources.InvalidStoreIdMessage.SafeFormat(storeId));

        // Find entity
        var store = await _service.FindByPrimaryKeyAsync(storeId.ToDomainStoreId(), cancellationToken);
        
        // Handle not found
        if (store is null)
            return NotFound(StringResources.NotFoundStoreMessage.SafeFormat(storeId));

        // Convert Domain → REST
        return Ok(store.ToRestStore());
    }
    catch (Exception ex)
    {
        return ServerException(ex);
    }
}
```

## Exception Handling (MANDATORY)

**ALL controller methods MUST use try-catch** to return structured errors according to `swagger.json` spec:

```csharp
public async Task<ActionResult<Rest.{Response}>> {Method}Async(
    /* parameters */,
    CancellationToken cancellationToken = default)
{
    try
    {
        // Method implementation
    }
    catch (Exception ex)
    {
        return ServerException(ex);
    }
}
```

### Why Try-Catch is Required

- **Structured Error Responses**: `ServerException(ex)` creates consistent error responses that match your OpenAPI error schema
- **Exception Type Handling**:
  - `NotFoundException` → 404 with error body
  - All other exceptions → 503 Service Unavailable with error body
- **User-Facing Messages**: Use a centralized string resources file for user-facing messages
- **No Stack Trace Leakage**: Structured errors prevent exposing internal implementation details

### {ServiceName}ControllerBase.ServerException

```csharp
[NonAction]
public virtual ServerUnavailableObjectResult ServerException(Exception exception)
{
    if (exception is NotFoundException)
    {
        return new ServerUnavailableObjectResult(
            value: _errorFactory.GetNotFound(exception.Message),
            statusCode: StatusCodes.Status404NotFound
        );
    }

    var error = _errorFactory.GetServiceUnavailable(exception.Message);
    return new ServerUnavailableObjectResult(error);
}
```

## Key Rules

1. **Spec-First**: NEVER create controllers manually. Define them in `swagger.json` first, and let NSwag generate the interface.

2. **Naming Convention**:
   - Generated interface: `Rest.I{Feature}Controller`
   - Implementation class: `{Feature}ControllerImpl`
   - Base class: your project controller base (`{ServiceName}ControllerBase`)

3. **Controllers are THIN**. They only:
   - Validate input (use `IIdentifierValidator`)
   - Convert REST ↔ Domain (use model converters, see [model-mapping](../model-mapping/SKILL.md) skill)
   - Delegate to services
   - Return appropriate status codes
   - Handle exceptions with `ServerException(ex)`

4. **MANDATORY try-catch** on ALL methods to return structured errors

5. **Long-running operations return `Accepted()` with session link**

6. **Use `StringResources` for ALL user-facing messages** (error messages, validation failures)

7. **XML documentation on implementation class** (methods inherit docs from generated interface)

8. **Model conversion**: Use model converters (see [model-mapping](../model-mapping/SKILL.md) skill)

## Response Status Codes

| Operation      | Success        | Failure                 | Returned By                                  |
|----------------|----------------|-------------------------|----------------------------------------------|
| GET single     | 200 OK         | 404 Not Found           | `Ok()` / `NotFound()`                        |
| GET list       | 200 OK         | -                       | `Ok()`                                       |
| POST (async)   | 202 Accepted   | 400 Bad Request         | `Accepted()` / `BadRequest()`                |
| POST (sync)    | 201 Created    | 400 Bad Request         | `Created()` / `BadRequest()`                 |
| PATCH          | 202 Accepted   | 400/404                 | `Accepted()` / `BadRequest()` / `NotFound()` |
| DELETE (async) | 202 Accepted   | 404 Not Found           | `Accepted()` / `NotFound()`                  |
| DELETE (sync)  | 204 No Content | 404 Not Found           | `NoContent()` / `NotFound()`                 |
| Any (error)    | -              | 503 Service Unavailable | `ServerException(ex)`                        |

## Checklist

- [ ] OpenAPI spec defined in `swagger.json` with `[TBD]` prefixes
- [ ] NSwag generated `Rest.I{Feature}Controller` interface
- [ ] Controller implementation named `{Feature}ControllerImpl`
- [ ] Inherits `{ServiceName}ControllerBase` and implements `Rest.I{Feature}Controller`
- [ ] Constructor calls `base(errorFactory)`
- [ ] `using Rest = {ProjectNamespace}.WebApi.AutoGenerated;` alias
- [ ] XML documentation on implementation class
- [ ] ALL methods wrapped in try-catch with `ServerException(ex)`
- [ ] Identifier validation using `IIdentifierValidator`
- [ ] User-facing messages use `StringResources` with `[TBD]` prefix
- [ ] Thin controller that delegates to services
- [ ] Async operations return `Accepted()` with session link
- [ ] Model converters created (see [model-mapping](../model-mapping/SKILL.md))
- [ ] CancellationToken on all async methods
- [ ] `cancellationToken.ThrowIfCancellationRequested()` at method start
